Linux：C 后端的相对路径，以及镜像要 gcc

用户要用 PyTorch 2.8.0 / Python 3.12 / Ubuntu 22.04 / CUDA 12.8，
而 C 后端只在 Windows/mingw 上跑过。查了一遍 Linux 假设，逮到一个真的：

    exe = os.path.join(args.workdir, "model.exe")
    subprocess.run([exe, ...])

POSIX 上相对路径没有 / 开头，系统不去当前目录找 —— FileNotFoundError。
Windows 会找，所以一直没露。改成 os.path.abspath。

by1cloud 的 /dev/null 也改了 —— 那是 Linux 的写法，而这个脚本从
Windows 上跑，Windows 的 ssh 认不出来。按平台选。

setup 现在会查 gcc，没有就装 build-essential —— 少它的话 by1all
整段 C 的检查会静默跳过，那不是失败，是少了一半验证。

镜像评过了：
  torch 2.8.0           用的 API 全是老的（rsqrt/tril/atan2/finfo）
  Python 3.12           按 3.9 语法解析 0 个文件不通过
  真第三方              只有 numpy / safetensors / torch / transformers
  transformers==5.15.1  存在，而且就是本机这个版本
                        （列表里最新是 5.19.0 —— 所以更要钉）
  Ubuntu 22.04          自带 gcc，本地的 mingw 坑没有了
  CUDA 12.8             支持 A800 的算力 8.0

另外加了密码引导：非交互的 shell 里没地方输密码，所以密码只能用来
做一件事 —— 把公钥装进 authorized_keys。之后全走密钥，密码只用一次。
