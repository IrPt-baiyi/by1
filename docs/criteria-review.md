# criteria-review.md —— 请人**重算**，不是请人"看看"

README 里有一句：

> 判卷人是外部的，但**判据是我定的** …… 它不告诉你这套判据是不是对的
> —— 而那件事**没有人替我验过**。

这份就是那件事的任务卡。它不是"帮我看看有没有问题"——那种请求没人接得住。
它是一份**几小时能做完、有确定判据的活**。

---

## 零、先说清楚：为什么这件事外人做才有意义

这个项目里两个数字的来源不同：

| | 谁给的 | 能不能被外人重走 |
|---|---|---|
| **原始数据**：某模型的 config 和权重清单 | **发布方**（在 `refs/` 里） | 能 —— 你自己读 JSON |
| **结论**：by1 说"我描述对了" | **我写的程序** | 能 —— 你手算一遍 |
| **判据**：什么算"对" | **我定的** | **这才是要你质疑的** |

前两行你能重走。**第三行是这个任务存在的理由。**

## 一、任务 A：手算三个模型的数字（约 1 小时）

### 做什么

从 `refs/` 里挑**三个**模型，**不看 by1 的任何源码**，自己数出：

1. 这个模型的**张量总数**
2. 其中有多少个能对上 by1 的命名规则（`refs/<模型>.index.json` 里有对照材料）
3. config 里有**多少个字段**，by1 的说法命中几个

然后把你的数字和 `docs/INVENTORY.txt` 的【A】段逐行比。

### 原始证据在哪

```
refs/<org>__<模型>.config.json     发布方的 config 全文
refs/<org>__<模型>.tensors.json    权重清单（名字 + 形状）
refs/<org>__<模型>.index.json      索引
```

`refs/SOURCES.tsv` 记着每个文件的出处。**这些 JSON 是发布方的原始产物，
不是 by1 生成的** —— 你可以直接用 `python -c "import json; ..."` 读。

### 什么算"对不上"

- 你数出的张量总数和 INVENTORY 不同 —— **这是硬错**，立刻报
- 个数一样但**名字对不上的不是同一批** —— 也是硬错，更隐蔽
- config 命中数不同 —— 报，并附上你数的方法

### 建议从这三个开始

在 `INVENTORY.txt`【A】里挑：一个**最小的**（`minimind-3`，90 个张量）、
一个**中等的**（`instella-3b` 399 个）、一个**大的**（`clef` 851 个）。
大模型更容易暴露"看起来对"的错误。

## 二、任务 B：手算一个 KV 状态尺寸（约 30 分钟）

挑一个 GQA 模型，从 `refs/<模型>.config.json` 里取
`num_attention_heads` / `num_key_value_heads` / `head_dim` / `num_hidden_layers`，
**自己推出**每 token 的 KV cache 字节数（按 fp16 算）。
再和 by1 声明的 state 尺寸比（`python src/checks/by1check.py <模型> --state`
或等价入口）。

**这一条特别值得做**，因为 by1 历史上在"头数 × 头维"这类地方错过 ——
而那种错**张量名和形状全对**，只有算出来的尺寸不对。

## 三、任务 C：试着补第 15 个模型（约 1 小时）

INVENTORY 的【A】是 **14 个**模型 —— 而这 14 个**是我挑的，不是随机抽的**。
这条我自己写进 README 了。

所以：**去找一个最近发布的、`refs/` 里还没有的模型**，把它的
config + tensors 拉下来，走一遍 `src/checks/by1triage.py`，看它是：

- **"又一个已覆盖"** —— 那说明这 14 个挑得还行
- **还是"又多一个新属性"** —— 那说明 14 这个数字是**挑出来的**，不是**抽出来的**

**第二种结果比再验一遍那 14 个有信息量得多。** 它直接指向
"这套覆盖面是不是自我选择的结果"。

（`by1triage.py` 是做这个用的，但你**不需要信它** ——
它的输入是 config JSON，你自己读也一样。）

## 四、最重要的一节：**`refs/` 判 `by1`，其实不是外部判卷**

这一条我自己得先说出来，否则上面那些任务会被误解。

by1 的命名规则、属性表、机制分类，是**照着这些 `refs/` 写出来的**。
所以：

> **`refs/` 全绿，说明的是"拟合得好"，不是"预测得对"。**

一个能说明问题的例子（`history/ir.md` 里记着）：`gpt2` 和 `llama-shaped`
一度**编译出同一份 IR** —— 两边对拍都是绿的，因为判据里根本没区分它们。
真正把它抓出来的是**加了 transformers 当第二个实现**，不是 `refs/`。

**所以最值得你质疑的不是数字，是这几样：**

1. **`1e-4` 那个阈值** —— 是我定的。它凭什么？
   （有个已经量到的事实：`by1e2e` 的误差从 seq 16 到 1024 会涨约 7 倍
   然后平台化，是 fp32 累积、不是结构错。**在 seq 16 上看着余量很足，
   那是假象。**）
2. **"什么算覆盖"** —— 一个模型"描述得出来"算什么？能前向算什么？
3. **那 14 个模型** —— 见任务 C。
4. **连 10 条神谕的期望值也是我写的** —— 一个"神谕"的期望值如果写错了，
   它会**稳定地**判错，而且看起来像被测的东西错了。

**如果你只能做一件事：挑一条神谕，自己推出它该输出什么，再比。**

## 五、你**不需要**读 by1 的源码

这是故意的。上面三个任务全都只要求：

- 会读 JSON
- 会做乘法和加法
- 会按字段名对照

**如果哪个任务让你必须读源码才能判断，那是这份任务卡写得不好，
请直接说。** 一个"要读懂实现才能验"的判据，本身就不算外部判据。

## 六、比对结果怎么报

```
我算的 / INVENTORY 说的 / 差在哪
你用的是什么（哪个 refs 文件、哪几行、什么命令）
你认为这算"我算错了"还是"INVENTORY 错了"还是"判据模糊"
```

第三种结果**不是失败** —— "判据模糊到两个人算出两个数"本身就是
这个任务想找的东西。
