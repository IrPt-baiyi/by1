# 删数据测试 · 第一次

## 测什么

用户提的性质：

> 如果这个仓库 **95% 的数据（不是代码）**全部被删除，
> **必须能够迅速重建**。
> 这意味着数据**不依赖硬编码**。

## 怎么测的

`test-definition/MANIFEST.txt` 里那 10 个路径，
占全部数据（25.99 MB）的 **4.75%** —— 按字节挑的，
而且**每一类至少一个**（纯按大小挑的话，
一个 `refs/*.tensors.json` 就能占满 5%，而 `*.by1` 一个都进不去）。

一个**完全无记忆的 agent** 拿到的是：

    test-definition/README.md      任务书（只说做什么、怎么算做完）
    test-definition/MANIFEST.txt   10 条：路径 + 字节
    __delete_test/files/...        那 10 个文件的副本

**没有源码、没有别的 24 个 `.by1`、没有别的 26 个 `refs/`。**
这一点很重要 —— 它比原设计难得多（原设计是"仓库拷贝减 10 个路径"）。

## 结果：9 / 9 逐字节对上，合计 1,234,405

| | |
|---|---|
| **7 个 `refs/` 产物** | **从上游推导重建** ✓ 逐字节相同 |
| **2 个手写文件** | **推不出来** ✗ 按副本字节恢复，**并明确标注** |

## 它逆推出了什么

`rebuild-record.md` 里那四种 JSON writer 的规则是**逐字节试出来的**：

    紧凑单行  separators=(",",":")      gpt2 / Nemotron / Laguna
    indent=0 + CRLF                     Qwen3-VL / GLM
    原样（连尾换行都没有）                gpt2 config
    LF -> CRLF（+28 字节）               DeepSeek config

**最阴的一条**：

> GLM 看着像单行，其实是**每个键一行 + `\r\n`**，值写成 `null`。
> 而且**排序只在每个分片块内部做** ——
> 全局排序会把它排错（`model.norm.weight` 会跑到第一个）。

**还有一条判据用得很干净**：Laguna 有两份 GGUF，
只有 `Q4_K_M` 的 `ggml_type` 分布和副本吻合（`BF16` 那份对不上）。

## 这次测试证明了什么

**按字节：95% 的数据是"上游产物的再导出" -> 可推导重建** ✓
**剩下 0.8%（`*.by1` + `models.tsv`）是手写的知识 -> 推不出来** ✗

**而依赖链是**：

    models.tsv   <-  可以从 `.by1` 头部的 `# by1-repo:` 推出来
    .by1         <-  手写的（shaped 类有兄弟文件可参照）

**两个手写文件互为支撑。** 删掉任意一个，另一个还能救它；
**只有两个一起删才断。**

## 而 agent 自己指出的边界

> 这两份的内容只能用 by1 那套源码（`by1*.py` / `ir.md` / `plan.md`）
> 来判对错，而那套源码不在这里。
> **没有它，这两个文件无法从零写对。**

**这句话是对的** —— 而它同时说明：
**"可重建"的性质，边界不在"数据有多大"，
在"手写的那一份有没有别的东西能交叉验证它"。**

## 复现

    python rebuild_manifest.py --out build

它的 `rebuild-record.md` 里记了上游 commit sha，可追溯。
