## 二、误差预算怎么推的

1. **同序同算子互拍**（NumPy↔PyTorch↔C↔ggml）：差只剩浮点算序与
   编译器优化。float32 机器精度 1.2e-7，一次 matmul 归约 √k 步累积 →
   实测 1e-7 ~ 3e-6。判据 1e-4 = **≥30 倍**余量。
2. **长序列会放大**：by1e2e 实测同模型 seq 16 → 1e-7、seq 1024 →
   9.3e-06；**有一个模型短序列 1e-5、长序列 7e-5 —— 贴着红线**。
   所以序列长度是预算变量，不是无关变量。
3. **bf16**：尾数 8 位，单步舍入 ~2e-3 量级；判据 2e-3/atol=rtol 是
   **单步**预算。链路每多一步乘 √2 的保守放大。
4. **真权重 ≠ 随机权重**：by1blind D 节的账 —— 嵌入表有大得多的值、
   量化权重天生带噪声。随机权重下的余量**不能**外推到真权重；
   真权重判据（2e-3）因此独立登记，不共享 1e-4。

## 三、守卫 eps **不是**判据阈值

`1e-30 / 1e-20 / 1e-9 / 1e-6` 这类数字出现在公式里是**数值护栏**
（除零保护、归一守卫），它们是**公式的一部分**（见
[prims-spec.md](prims-spec.md) 的 bound 列），改它们 = 改公式，
不是调判据。两者的纪律：

- 判据阈值：登记在本文，改它要先解释余量为什么变了。
- 守卫 eps：跟着公式走，`by1graph.PRIMS` 的 `f`/`bound` 是唯一事实。
  **`+1e-20` 和 `max(·,1e-9)` 是两个公式**，历史上混过一次（MoE 归一）。

## 四、已知的贴线点（不许当没看见）

1. **by1exec `--compare` 的 1e-5**：实测最大 2.85e-06，余量 3.5 倍 ——
   全表最紧的一行。qwen3-next-shaped 换个编译器就可能贴线。
2. **长序列**：7e-5 @ 大 seq 的实例（by1e2e 注释里的表）离 1e-4 只有
   1.4 倍。RoPE / sliding window / YaRN 全是长序列才现形的东西
   （by1blind B 节：最大查过 seq 512，最大 ctx 1048576）。
3. **依赖没钉版本**（by1blind G 节）：numpy/torch 是数值结果的根源，
   判据是 1e-4 量级，换小版本可能改结论。
