# 对 `pattern-design.md` 的审查

> 审查方式：把草案里每一条**能核的主张**拿去和代码对。核不了的单列。
> 结论先给：**方向对，但草案的自我评价（§7「六个全部通过」）和它的实际
> 完成度差得比较远。它关掉的是一个缺口，不是十六个。**

---

## 一、草案提的语法，代码已经支持了

写了份临时探针实际跑了一遍（测完就删了）：

```
mech Attention : Attention { heads = { q = 4, kv = 2, head_dim = 16 } }

schedule {
  block = 2 * Attention(window = 128)
}

stack main {
  pattern = 2 * block + 1 * Attention(window = none)
  main[where window = 128] >> MLP
}
```

`by1check` 的输出：

```
展开层表
  main              5 层
    4 x Attention(window=128) + Attention(window=none)
```

**机制实例带属性（§1）、命名子序列（§3）、`where` 选择器（§5）——
三样都通。** 唯一报的错是 `hparams.n_layer = 4，但主栈合计 5 层`，
那是我探针里故意写岔的数，正说明层数推导（§4）也在工作。

所以 §1/§3/§4/§5 里"核心改动"那部分**不是改动，是现状**。

## 二、Q1 已经被代码决定了

草案 §9 的 Q1 是"`SWA` 要不要作为独立机制存在"，倾向"不要"。

**代码早就答了**：`TOKEN_MIXER`（`by1check.py:659`）里没有 `SWA`。
`SWA` 只能作为**用户自己声明的机制名**出现，种类仍是 `Sparse`。
`drafts/deepseek-v4.1-flash.by1:40` 写的 `mech SWA : Sparse` 正是这个用法。

Q1 不用拍板了，它已经落地。

## 三、§5 那两个原语，代码里一个都没有

这一条是草案和现实差距最大的地方。

```
prev\(             没有
shared_from        没有
inherit\(          没有
candidates_from    没有
```

注意这两个名字 —— `prev` 和 `shared_from` —— 是**草案自己发明的新词**，
不是现有语法的写法。草案 §5 说它"同时解决两个缺口"：

```
d[where mode = reuse].CSA2.kv_cache : shared_from(prev(CSA2 where mode = reindex))
d[where mode = reindex].CSA2.index  : inherit(candidates_from = prev(Sparse))
```

**这两行现在是散文，不是语法。** 它们对应的缺口 7 和缺口 3/8
在草案里被写成"已解决"，但没有任何一行代码认得这两个词。

顺带纠正一处措辞：草案 §5 说"`>>` / `::` / `state` / `position` /
`tensors` 五个块都要能寻址层，所以只定义一套选择器"。

**`where` 目前只在一个地方实现**（`by1check.py:108`），
不是五个块。这是一条待办，不是一条已完成。

## 四、§6④ 和代码直接冲突：KDA

草案写：

```
mech KDA : Linear { ... }        # Kimi Delta Attention
```

而 `by1check.py:669-672` 有一整段注释说为什么**不能**这么写：

> KDA（Kimi Delta Attention）：和 GDN 同族但**不是同一个东西** ——
> 三个独立卷积、`f_proj`、`o_norm`。当成 Linear 会生成一个 GDN，
> **那是个"看起来对但算错"的模型**，所以给它自己的种类。

**这是草案里唯一一处会引入 bug 的地方**，而且正是这个项目一直在防的那一类
（"能描述 ≠ 能算"）。KDA 在代码里是独立种类，草案把它降回 `Linear`。

改法：草案 §6④ 写成 `mech KDA : KDA`，判族讨论放在文字里，不要写成语法。

## 五、§7「六个全部通过」是纸面推演

那张表的每一行都是"分析一下，能表达"。而这个项目的判据是**能不能跑**。

实际状态：

| 验收模型 | 有 `.by1` 吗 | 过检查器吗 |
|---|---|---|
| GPT-OSS-120B | 有（`models/`） | 过 |
| Gemma 4 31B | 有（`models/`） | 过 |
| Qwen3.8 | 有（`models/Qwen3.8-27B.by1`） | 过 |
| DeepSeek V4.1 | **草稿**（`drafts/`） | **1 错 7 警** |
| Kimi K3 | **没有这个文件** | —— |
| Nemotron 3 | 有（`models/NVIDIA-Nemotron-3.5-…`） | 过 |

**六个里有三个是已发布的 `.by1`，两个是草稿，一个是纸面反推。**
把它们并排打勾，等于拿"三份验证过的"给"三份没验证的"背书。

尤其 K3 —— 草案 §6④ 自己写着"**但这是我反推的，不是公布的划分方式，
需要核对**"。那么它就不能算"通过"，只能算"没找到反例"。

## 六、十六个缺口，草案实际关掉一个

`drafts/deepseek-v4.1-flash.by1` 里标了 16 个缺口。逐个对：

| 缺口 | 内容 | 草案的态度 |
|---|---|---|
| **2** | `mode` 不是机制类型（**立项的那个**） | **真的关掉了** —— §6⑤ 那三行 `+` 就是答案 |
| 3 / 8 | 索引器候选集沿层传递 | §5 给了名字（`inherit`），**没实现** |
| 7 | Reuse 引用另一层的 KV | §5 给了名字（`shared_from`），**没实现** |
| 6 / 13 | 跨栈接线 | §8 明确划出去 |
| 9 | SWA 持久化 | §8 明确划出去 |
| 16 | optimizer | §8 明确划出去 |
| 12 / 15 | 多段栈 + 全局层编号 | **已经过期** —— 代码支持多段栈（`for st in stacks`），草案文件里也真的写了 `stack encoder` / `stack decoder` |
| 1 | 激活参数按执行阶段不同 | **草案一个字没提** |
| 5 | mHC 与 Gated Residual 同轴不同族 | **没提** |
| 10 | 精度是按状态的，不是全局 dtype | **没提** |
| 11 | 权重 vs 请求级小状态 | **没提** |
| 14 | position 按模态分区 | **没提** |

**五个缺口草案完全没提**（1/5/10/11/14）。它们确实不归 `pattern` 管 ——
但 §8"本方案明确不解决的问题"那一节也没列它们，读的人会以为边界就是那五条。

## 七、草案里真正有价值的一条

§2 的判族规则：

> **两个变体同族 ⟺ 它们的状态契约相同。**
> 差异只是标量参数或 mask 语义的，同族；一旦多出一份状态，就分族。

这一条比草案里任何语法都重要，因为它是**可判定的** —— 不用争"像不像"，
只看状态契约。而且它自己承认代价：

> 我上一轮给你草拟的那张 11 族表**作废了**，它按"功能像不像"切，切得太松。

**一个方案能推翻自己上一轮的结论，这条就值得信。**

## 八、所以真正的下一步是什么

草案的 §10 落地顺序是"你答 Q1–Q5 → 重写 deepseek → Gemma 4 压测 →
张量契约单独定一版"。按上面的核查，这个顺序要改：

1. **Q1 不用答了**（代码已经定了）。Q4 也不用 —— 层数推导和断言都在工作。
   Q2 和 Q5 是**真问题**，但 Q5 是显示层的，可以先放。
   **剩下一个真需要拍板的是 Q2。**
2. **Q3 已核实**，草案自己标了。
3. **重写 deepseek 草稿之前，先做张量契约的实例化。** 检查器现在报的
   `[W] tensors 的 'GQA.layer(i)' 契约是空的` 就是这个 —— 而 §2 规则 3
   说结构属性被覆盖时契约必须能按实例展开。
   **先定契约，再写模型**，否则重写完还是要回头改。
4. **`prev()` 那套跨层原语要么实现、要么从草案里划到 §8。**
   现在它挂在"已解决"的栏目里，而代码里没有这个词 ——
   这是最容易误导后来人的一处。
5. **K3 要么补一份 `.by1` 和它的判卷人，要么从验收表里去掉。**
   拿反推的划分方式当"通过"，和这个项目的判据不符。

---

## 九、一句话

**草案的立论（属性不是平权的、判族看状态契约）是对的，而且它关掉了
它自己立项的那个缺口。但它把"想清楚了"写成了"做完了" ——
§5 的两个原语没有实现，§7 的六个通过里有三个没有判卷人，
§6④ 还和代码冲突。**

**这不是一份可以照做的施工图，是一份想得比较透的立项书。**
