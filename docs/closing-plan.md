## 一、分档原则

- **做**：本地能做、判据可复核、不依赖外部资源（权重 / 显卡 / 上游合入）。
- **延期**：依赖外部资源，或「做一半反而更糟」；**每条必须写再验证条件**，不是「以后再说」。
- **不做**：产品边界（见 `docs/product-definition.md` 的 S7 四条）—— 列出来是为了防误记，不是缺口。

## 四、不做（产品边界，防误记）

`docs/product-definition.md` 的四条边界：通用运行时、自研 CUDA 量化器、改 GGUF 语义、覆盖计数。
另外**不追上游新架构**：只按 §三 的 watch 条件重启，不主动扩家族。

## 五、节奏

1. 每轮从 §二 取一件，做完就把 §二 对应的行改成「已做（第 N 轮）」并在 `docs/gap-analysis.md` 同步一句；
2. 每轮**不许新增 §二 的项**，除非它同时满足「本地可做」「可复核」「不是加固判据的无限游戏」；
3. 当 §二 清空、且**连续两轮**只产出记档（D3），就执行 D4，然后结束；
4. 延期项**不做也不弃**：它们带着再验证条件留在 §三，随时可以重开。
