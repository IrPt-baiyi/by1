从产物反推：by1boot.py

为什么是这一件
--------------
量过：一份 .by1 里 27% 是决定、64% 是机械。机械那一半里：

    张量契约   机制 + 属性 -> 名字和形状     by1contract.py 已经能推（形状）
    导出命名   「这个仓库怎么命名」           推不出来 —— **除非问产物**

而产物就在那儿。by1verify 每天在读 config 和 safetensors 头，
只是只拿去比对、不拿去生成。

它真正的形状
------------
**它不是"帮你写 .by1"，是把"你必须懂 73 个属性"换成"你改到验过为止"：**

    by1boot   ->  草稿
    by1verify ->  哪里对不上
    你改       ->  直到全绿

草稿对不对**不需要你判断 —— 判卷人判断**。
这才是"不懂也能写"那条路的真身：不是让他写，是让他改，
而且改到哪儿算对由机器说了算。

by1boot.py 能做什么
-------------------
从 config + safetensors 头反推：

    ✓ hparams（d_model / n_layer / vocab / rms_eps）
    ✓ 每层是什么机制（按张量名认：self_attn.* / linear_attn.* / mixer.*）
    ✓ 每层挂的是什么（mlp.* / experts.*）
    ✓ **契约 —— 直接从产物里读名字和形状**

实测两个：

    minimind-3   8 层 Attention + 8 层 FFN，13 类张量
    nemotron    23 Linear + 6 Attention + 23 MoE（还有 23 层认不出来 —— 它说出来了）

反推不出来的（config 里没有、产物只有名字和形状）
------------------------------------------------
路由方式 / 有没有共享专家 / 门控激活 / per_expert 还是打包 /
bias / rope 的缩放类型。**这些只能靠 by1verify 逼出来。**

一路上抓到的两个
----------------
1. 按"这一层是什么机制"分桶，于是 mlp.* 全被塞进了 Attention 桶 ——
   名字对、形状对、**分错组**。分错组的表现是"Attention 里有 mlp"，
   一眼能看出来，**前提是你去看**。
2. 形状的元组格式化成 (768, 2432,) —— 单元素元组的写法。
   不影响正确性，但它是个信号：那段格式化没为"一维"写过。
