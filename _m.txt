云端：A800 上跑通了，顺带修了三个可移植性 bug

用户给的实例：A800 80GB / torch 2.8.0+cu128 / cuda 12.8 / 算力 8.0。
**显卡验证过了** —— 9 个模型 CPU vs CUDA 相对差 3e-07 ~ 1.2e-06。

一路上三个 bug，全是"只在 Windows 上跑过"：

1. OpenSSH 走不通。AutoDL 那个网关的 sshd 不认
   publickey-hostbound-v00@openssh.com（OpenSSH 8.2+ 的客户端扩展）。
   现象很误导：服务端 debug 说 Server accepts key，然后 Permission denied。
   公钥在 authorized_keys 里、权限 700/600、pubkeyauthentication yes
   —— 全对，就是不通。**改成 paramiko 走 SFTP 和 exec。**

2. 非交互 SSH 的 PATH 是极简的 —— python / pip / gcc **全都找不到**。
   **一个原因三个症状**，我一开始当成三件事查。
   现在 ssh() 里显式补 PATH。

3. find_gcc 只写了 Windows 的路径。加了 Linux 路径之后**还是不行** ——
   因为 glob.glob('gcc') **不搜 PATH**，只找当前目录。
   裸名字要用 shutil.which。
   **一个看起来加了、其实没生效的修复，比没加更坏。**

还有：cmd_run 原来是四步各开一个连接，被网关限流
（Error reading SSH protocol banner —— 那个报错长得像网络问题，
其实是"你连太快了"）。现在合成一条远程命令。

remote-run.sh：从 Windows 一条条 ssh 发命令，引号会被吃好几层，
写成一个脚本一次跑完。
