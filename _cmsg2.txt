GPT-2 的前向跑通了：1.058e-06，真实维度，对 HF 官方实现

为什么做这个
------------
从头审视发现：gpt2.by1 和 llama-shaped.by1 编译出的 IR 算子序列
一模一样 —— gate = none 变成 gate: true，RMSNorm 顶着 GPT-2 的
LayerNorm，而三个后端、by1verify、by1all 全说「过」。

根因是那一行 str(attrs.get("gate","true")).lower() != "false"，
以及更深的一层：语言里根本没有地方能说「我要 LayerNorm」——
ops_of 里 {"mech": "RMSNorm"} 是写死的。这不是「默认值选错了」，
是「只能 RMSNorm」。

所以这一轮的目标不是「多一个模型」，是让「另一代」真的能算。

结果
----
    by1gpt2.py   权重搬运 197/197
                 最大绝对差 2.742e-06   相对 1.058e-06
                 [PASS] GPT-2 的前向与官方实现一致

判卷人是 HF 的 GPT2LMHeadModel：官方 config、维度全真（d=768 层=12
头=12 vocab=50257）、124M 参数。权重是随机初始化的 —— 对拍前向
不需要真权重，两边喂同一组就够。

补上的三样「另一代」的东西
--------------------------
1. LayerNorm —— 不只是「多一个 bias」，它还要减均值。
   hparams.norm_kind = layer 说出口；ops_of 和 By1Model 两处都要认
   （第一版只改了前一处，GPT-2 建出来是 24 个 LayerNorm + 1 个 RMSNorm，
    而那个 1 就是最终归一化）。
2. 学习式位置编码（wpe）—— 一张学出来的查表、加在输入上，
   和 RoPE（旋转、在注意力里）是两种东西。
3. 无门控 MLP + GELU —— 以及 gelu_new（tanh 近似）和精确式不能混。

它逼出的四个 bug，全是同一类：「不存在的机制表达不出来」
-------------------------------------------------------
1. gate = none        -> gate: true      （无门控说出口没用）
2. 无门控分支硬编码    -> F.silu(g)       （act 被丢）
3. MLP 硬编码 bias=False -> GPT-2 的 c_fc/c_proj 的 bias 被丢，
   而「权重搬运 173/173」看起来是满的 —— 那 4x12 个参数根本不在我的模型里
4. Attention 无条件 apply_rope -> GPT-2 被静默转了一遍
   线索其实早就有了：用同一组 wq/wk/wv 手算，和我的实现差 1.4e-02。
   同一组权重、同一个公式，差 1.4e-02 —— 那只可能是多算了一步。

顺手做的
--------
- 取值门（ENUMS + _enum_bad）：act / qk_norm / routing / gate_act / pairing
  的取值必须在实现过的集合里。加上可证伪对照 by1gate.py：
  gate-probe / nemotron / ling 三个必须被拒，clef-tiny / step-3.7 / gpt2
  三个必须通过。
- 对照自己抓到过一次：把 gelu 实现之后，GPT-2 从「必须被拒」变成
  「必须通过」，而对照列表没跟着改，于是它立刻红了。那是它该干的事。
- 抓到 routing = sigmoid_topk 一直在走 softmax（Step-3.7）。它的 config
  是 sigmoid + 无分组，所以 .by1 写的对、是 RUNTIME 没有这一支。
  step-3.7 的前向从来没跑过（180B），所以一直没人发现 ——
  而它的 config 46/46、张量 728/753 都是对的，因为那些查的是命名和形状。
